### Why the verifier itself was the drift source

The post-Session 1102 taxonomy CLAUDE.md update (when CodeGeneratorAgent
moved out of the AgentControlEntry blocklist and into the hardcoded
`_NON_SPECIALIST` reroute set in `core/epa_handlers/td_handlers_ops.py:3618`)
correctly shifted the counts to `73 / 9 / 1`. The verifier function
`_claude_agent_taxonomy` was left carrying the pre-1102 hardcoded numbers
(`73 / 8 / 2`) in both its `description` string and its `expected_claim`
constant. So the verifier and reality were both correct individually —
they just disagreed.

Fix is at
[`core/services/doc_claim_verification.py:1854-1874`](../../core/services/doc_claim_verification.py):

```python
# Refreshed Session 1115 — matches current CLAUDE.md (73/9/1)
expected_claim = "73 enabled + 9 rerouted + 1 blocked = 83"
actual_claim   = f"{fully_enabled} enabled + {len(rerouted)} rerouted + {len(blocked)} blocked = {total}"
matches = (fully_enabled == 73 and len(rerouted) == 9 and len(blocked) == 1 and total == 83)
```

Description string also bumped from `8 rerouted, 2 blocked` to
`9 rerouted, 1 blocked` so the claim's own self-description matches.

## How to keep this honest going forward

- **Add a verifier claim for any count you cite in canonical docs.** The
  registry under `core/services/doc_claim_verification.py` is the
  drift-detection source of truth. Static checks (no DB) survive CI;
  DB-backed checks surface real-data drift locally.
- **Refresh the autoblock only with DB up.** `python manage.py
  refresh_doc_inventory_blocks` rewrites `<!-- @inventory-block:* -->`
  segments. Without Postgres it silently sets `Agents` / `Beat
  Schedule` rows to `n/a`. Run `python manage.py generate_platform_inventory`
  alongside it to keep `docs/PLATFORM_INVENTORY.md` current.
- **Don't hand-edit autoblocks.** The two markers in CLAUDE.md and the
  three in AGENTS.md / topic docs regenerate. Manual tables (the
  "Detailed Breakdown" in CLAUDE.md, plus handoff narratives) are
  fair game.
- **`context-kit verify --json` corpus findings are advisory.** They
  flag historical drift across 1900+ docs (handoffs, audits, reviews) —
  intentional under the "never delete docs" rule. Only `CONFLICT`
  findings block PRs via `verify_repo_guardrails.py`; `DOC_ONLY` is
  informational.
