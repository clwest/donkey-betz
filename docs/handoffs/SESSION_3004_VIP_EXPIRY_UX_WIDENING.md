## Design decisions ratified by Rigby A2 SIGN

1. **Header vs body-string vs envelope discriminator.** Chose HTTP header (`X-VIP-Expired: true`). Rationale: (a) shipping today without cross-slot dependency on T-ENVELOPE-2 Chris D-verdict; (b) headers are the idiomatic HTTP discriminator for response *category*; (c) forward-compat with a later APIResponseEnvelope Family B migration — the header can persist as a category hint for one release.

2. **Single discriminated authFailureStore vs parallel `vipExpiredStore` sibling.** Chose discriminated authFailureStore (Rigby STRENGTHEN α). Rationale: adds ~15-30 min to base estimate today, saves ~45-60 min future consolidation cost when a 3rd 401 semantic class appears (workspace-suspended, subscription-lapsed, etc.). Substrate-right first pattern; extending is one enum entry + one modal branch instead of a full store migration.

3. **Shared `AUTH_FAILURE_KIND` const vs raw string literals.** Chose shared const (Rigby STRENGTHEN 6a). Literals had appeared in three sites (store type, handler assignment, modal branch); const-referencing prevents typo drift.

4. **VIP-expired CTA redirect target `/` (rejected `/vip/`).** grep of `frontend/src/App.tsx` shows the only `/vip/*` route is `<Route path="/vip/accept" element={<VipAcceptPage />} />` at line 72 — bare `/vip/` would render the catch-all/404. `/` is the stable DemoHomePage (`DemoHomePage.tsx`). `/login` also rejected because re-login won't recover VIP entitlement. Rigby AGREE'd rationale after re-inspection.
