# Connectivity Sweep Plan

**Date:** April 5, 2026
**Status:** Planning — to execute after DeliverableFactory migration complete
**Triggered by:** Chris observed Ironwood sprites not appearing in workspace Images tab

---

## Root Problem

Media models (ImageHistory, VideoHistory, AudioHistory) have **no workspace field**. There's no way to link generated images/videos/audio to a specific workspace. The Images tab in workspace likely queries user-uploaded content only.

## Findings from Local DB Audit

| Model | Count | Workspace Field | % Without Workspace |
|---|---|---|---|
| ImageHistory | 236 | NO FIELD | 100% (field doesn't exist) |
| VideoHistory | 7 | NO FIELD | 100% |
| AudioHistory | 33 | NO FIELD | 100% |
| Deliverable | 411 | Has field | 100% (all NULL) |

**98% of deliverables have no user assigned** — agent-created content with no ownership.

## Impact

1. **Ironwood sprites** — generated by management command, saved to disk + ImageHistory, but can't appear in Ironwood workspace because ImageHistory has no workspace FK
2. **Agent-generated images** — PA creates images via ImageStudio tools, saves to ImageHistory, but no workspace linkage
3. **All deliverables** — locally, zero deliverables linked to any workspace. Production may differ (workspace assignment was fixed in earlier sessions) but scheduled agent output has no workspace context

## Required Fixes

### Phase 1: Add Workspace FK to Media Models

```python
# content/models.py — ImageHistory, VideoHistory, AudioHistory
workspace = models.ForeignKey(
    'core.ProjectWorkspace',
    on_delete=models.SET_NULL,
    null=True, blank=True,
    related_name='images',  # or 'videos', 'audios'
    db_index=True,
)
```

- Requires Django migration
- Backfill: match images to workspaces by user + creation time proximity

### Phase 2: Wire Workspace Assignment into Creation Paths

Every path that creates media needs to pass workspace_id:
- `core/agents/image_generation_agent.py`
- `core/services/tool_dispatcher.py` (image_generation handler)
- `core/tasks_media.py` (thumbnail generation, etc.)
- PA tool handlers (`davinci_tool`, `media_tool`)
- Management commands (sprite generation, etc.)

### Phase 3: Fix Workspace Tab Queries

The workspace Images/Media tab needs to query:
- Deliverables with image content in this workspace
- ImageHistory records linked to this workspace
- VideoHistory records linked to this workspace

### Phase 4: Backfill Historical Data

- Match existing ImageHistory records to workspaces by user + app context
- Match existing Deliverables to workspaces (the DeliverableFactory now auto-assigns, but historical records need backfill)

### Phase 5: Rigby Integration

Ensure when Rigby creates images/content for an app workspace:
1. The image is saved to ImageHistory with workspace_id
2. A Deliverable is created linking to the image with workspace_id
3. The content appears in the correct workspace's Images/Deliverables tab

## Estimated Scope

- 1 migration (add workspace FK to 3 media models)
- ~10 files to update creation paths
- 1 backfill management command
- 1 frontend fix (workspace tab queries)
- Testing: verify end-to-end from "Rigby create image" → appears in workspace
