## A1: API Security Hardening

### A1.1-A1.3: Authentication Enforcement

**Problem:** 48 API path prefixes were listed in PUBLIC_PATHS, exempting them from authentication.

**Solution:** Reduced PUBLIC_PATHS to only truly public endpoints:

**Before (48 paths):**
```python
PUBLIC_PATHS = [
    '/api/v1/health/',
    '/api/opportunities/',      # REMOVED - needs auth
    '/api/income/',            # REMOVED - needs auth
    '/api/memory-palace/',     # REMOVED - needs auth
    '/api/agent-dashboard/',   # REMOVED - needs auth
    # ... 44 more paths removed
]
```

**After (11 paths):**
```python
PUBLIC_PATHS = [
    '/api/v1/health/',         # Health checks
    '/health/',
    '/api/v1/auth/login/',     # Auth endpoints
    '/api/v1/auth/register/',
    '/api/v1/auth/forgot-password/',
    '/api/v1/auth/reset-password/',
    '/api-auth/',
    '/api/discord/verify-link-code/',  # Webhooks (use secrets)
    '/api/stripe/webhook/',
    '/admin/',                 # Django admin (own auth)
    '/api/public-stats/',      # Intentionally public
]
```

**New Feature: Optional Auth Paths**
```python
OPTIONAL_AUTH_PATHS = [
    '/api/voice-marketplace/',  # Browse public, purchase requires auth
    '/api/monitoring/',         # Public dashboard
]
```

**File Modified:** `core/auth_middleware.py`

### A1.4: CSRF Exemption Review

**Finding:** 96 view files have CSRF exemptions.

**Assessment:** Appropriate for API endpoints because:
1. Token authentication is required (handled by middleware)
2. CSRF attacks rely on browser auto-sending cookies
3. Token auth requires explicit header inclusion
4. Middleware validates tokens/sessions before allowing access

**Conclusion:** No changes needed - CSRF exemptions are correct for token-authenticated APIs.
